# 诗经 · 四书 · 语料与统计分析

[![CI](https://github.com/RevolutionLA/shijing/actions/workflows/ci.yml/badge.svg)](https://github.com/RevolutionLA/shijing/actions/workflows/ci.yml)

对传世典籍做**结构化**与**可复现统计**的 Python 工具包。现有语料：《诗经》305 篇
29,645 字与《四书》的**经文**（不含注疏）——《论语》20 篇 512 段、《孟子》
14 篇 690 段、《大学》1 篇 16 段、《中庸》1 篇 39 段，合计 341 篇、86,269 字。
带命令行、字频词频、复沓（重章叠句）与**上古音口径**的韵脚分析、跨平台字云词云，
以及跨典籍的候选名出处核验。

```bash
pip install -e ".[dev]"
shijing report                       # 一次性输出全部指标（默认只看诗经）
shijing --book 论语 chars --top 10    # 换一本典籍，字频/词频/检索/出图同样能跑
shijing refrain --what shared --top 10   # 跨篇套语
shijing rhyme --poem 关雎                  # 逐句韵脚（上古音口径，诗经专属）
shijing name 之恒                           # 候选名核验：默认跨诗经+四书查出处
```

## 这个仓库原来有什么问题

原版是三个各约 20 行的脚本（现留在 [`legacy/`](legacy/)）。重做前先做了数据体检，
结论是：**问题主要不在代码，在数据。**

| 检查项 | 原状态 | 现在 |
|---|---|---|
| 编码 | 三个脚本都写 `encoding='gbk'`，而 `shijing.txt` 实际是 **UTF-8**，直接跑必崩 | 统一 UTF-8，路径可配 |
| 文本路径 | 写死 `C:\xxxxxxxxx\shijing.txt` | `data/raw/` + 自动定位，任意工作目录可跑 |
| 重复粘贴 | 4091 行里 **2514 行（约 61%）是整段重复**；`周頌·清庙之什` 出现 5 次 | 按正文指纹去重，305 篇 |
| 字数 | **84,455** 字，是真实篇幅的 2.8 倍 | **29,645** 字 |
| 繁简混排 | 「周頌」与「周颂」、「撻奮」与简体混在一起，同一个字被拆成两笔账 | 统计走归一字形，存档保留原文 |
| 分组串台 | 粘贴段丢失分组标题，齐风的《南山》等 6 篇被挂在`国风·曹风`下 | 跨粘贴多数表决 + 显式覆盖表 |
| 表格残留 | `维鹈在梁，不?/td>` 这类网页表格残留，且伴随脱字 | 剥离标签，脱字**如实报告**不臆造 |
| 篇名解析 | 五字篇名《昊天有成命》会被漏掉 | 支持 1–6 字篇名 |
| 字云统计口径 | `Counter(text)` 把标点、换行都算成"字" | 只统计汉字 |
| 出图 | 硬编码 `simhei.ttf` + `plt.show()`，无显示环境即崩 | 跨平台字体探测 + 落盘 PNG |

修正后的篇数是**自证式**的：国风 160 / 小雅 74 / 大雅 31 / 周颂 31 / 鲁颂 4 / 商颂 5
= **305 篇**，与《毛诗》篇数完全一致；字数从 8.4 万回落到 2.96 万，也落回《诗经》
应有的量级。这两条都写成了回归测试，防止再退回去。

## 语料结构

`shijing build` 从原始文本重建 `data/corpus.json`；换典籍就加 `--book`：

```jsonc
{ "idx": 1, "group": "国风·周南", "part": "国风", "title": "关雎",
  "stanzas": ["关关雎鸠，在河之洲。窈窕淑女，君子好逑。", ...],
  "versions": 3,        // 合并了几个重复版本
  "book": "诗经" }
```

- `data/raw/shijing.txt` — 原始抓取文本，**一字不改地存档**，用于溯源
- `data/t2s.tsv` — 繁→简归一表（4053 条，只登记繁简有别的字），构建期用 zhconv 生成后冻结，**运行时不依赖 opencc/zhconv**
- `data/overrides.json` — 人工裁定表，逐条写明理由，可审计
- `data/books/<slug>/raw.json` — 四书的上游原文（chinese-poetry，MIT），同样一字不改存档；
  四个文件的 git blob 校验和写进了 `tests/test_books.py`，克隆下来重算仍能与上游对上
- `data/books/<slug>/corpus.json` — 由 `shijing --book 论语 build` 生成的结构化语料
- `data/books/LICENSE.chinese-poetry.txt` — 上游 MIT 许可证全文（MIT 要求随副本保留）

模型的对应关系是：**篇 = `title`，章/段 = `stanzas`**。诗经的"章"是重章叠句的那一章，
四书的"章"是上游的分段（《论语》16 段/《学而》），两者共用同一套结构与绝大多数分析。

## 命令

| 命令 | 作用 |
|---|---|
| `build` | 重建语料；`--book 论语` 换典籍（写在 `build` **前面**），`--regen-t2s` 重建归一表 |
| `chars` / `words` | 字频 / 词频（jieba 分词，可 `--keep-stopwords`） |
| `refrain` | `parallel` 章际平行度、`redup` 叠字、`shared` 跨篇套语 |
| `rhyme` | 韵脚：`--system ancient`（默认，取 Baxter 标注）/`modern`；`--what summary`/`table`/`compare`/`verify`（与表内原文逐字对照） |
| `cloud` | 字云 / 词云出图，`--font` 可指定字体 |
| `search` / `show` | 全文检索（繁简互通）/ 打印原文 |
| `name` | 候选名核验：连用出处 + 整篇语境 + 用字档位 + 普通话读音（**默认跨典籍**） |
| `report` | 全部指标一次输出 |

`--format table|json|csv`，`--poem 关雎` 限定单篇，`--book` 选典籍（`all` 合并全部已构建的，
默认按命令而定：只有 `name` 默认 all，其余默认诗经）。

**文体门控**：`rhyme` 与 `refrain --what parallel` 只对诗经开放，其余典籍上会直接报错说明
原因，不会给出一本正经的无意义数字：

```console
$ shijing --book 论语 rhyme --poem 学而
韵脚是韵文口径的分析，当前语料是论语；诗经的重章叠句结构与逐句韵脚标注（按 305 篇
键控）在散文典籍上都不成立。
```

```console
$ shijing refrain --what shared --top 4
line      poems  where
心之忧矣  11     国风·卫风·有狐、国风·曹风·蜉蝣、国风·邶风·柏舟 …
既见君子  9      国风·周南·汝坟、国风·唐风·扬之水、国风·秦风·车邻 …
万寿无疆  6      国风·豳风·七月、小雅·南有嘉鱼之什·南山有台 …
```

## 拿来给孩子或项目起名

`shijing name 候选名` 不是"取名器"，是**出处核验器**。它只回答能被这 341 篇证实的
四件事，把"这个名字好不好"留给你自己判断。检索范围默认是**诗经 + 四书**（要收回单本
就加 `--book 诗经`），因为「如月之恒」在《诗经》、「茍日新，日日新，又日新」在《大学》，
取名时想的是同一件事。先看一次完整输出：

```console
$ shijing name 之恒 --no-context
候选：之恒    连用命中 1 处    检索范围：诗经、论语、孟子、大学、中庸（341 篇）
典籍  分组       篇名  章  原句
--  -------  --  -  ---------------------------------
诗经  小雅·鹿鸣之什  天保  6  如月之恒，如日之升。如南山之寿，不骞不崩。如松柏之茂，无不尔或承。

用字：
字  次数    所见篇数  档位   备注
-  ----  ----  ---  --
之  3770  266   极常见  虚词
恒  27    13    较少

读音（普通话）：
字  拼音     声调  声母  韵母   又读
-  -----  --  --  ---  ---------
之  zhi1   1   zh  i    zhu1、zhi4
恒  heng2  2   h   eng
```

四栏各自能防的坑：

1. **连用命中**——两个字都在库里出现过，不等于它们连用过。`shijing name 德棣` 命中
   0 处：德、棣各自都有，但这个组合是拼的，没这句。此时命令会接着**逐字给出处**，
   让你自己判断这是"有典的拼合"还是"无典的杜撰"：
   ```console
   $ shijing name 徐铎
   候选：徐铎    连用命中 0 处    检索范围：诗经、论语、孟子、大学、中庸（341 篇）
     诗经、论语、孟子、大学、中庸里没有这两个字连用的句子——单字都有，也可能只是拼凑。

   单字出处：
     徐：（共 13 处，列前 3）
       诗经·大雅·荡之什·常武 第4章：率彼淮浦，省此徐土，不留不處，三事就緒。
       诗经·大雅·荡之什·常武 第6章：徐方繹騷。震驚徐方，如雷如霆，徐方震驚。
       诗经·大雅·荡之什·常武 第10章：如川之流。绵绵翼翼，不測不克，濯征徐国。
     铎：
       论语·八佾篇 第24章：…出曰：“二三子何患于丧乎？天下之无道也久矣，天将以夫子为木铎。”
   ```
   这条最能说明为什么要并书：只看《诗经》时"铎"是全库未见，并上《论语》之后它其实
   有典——「天将以夫子为木铎」，只是这个典在《论语》而不在《诗经》。而"徐"两书都只
   出现在征伐徐国的篇章里，全作敌对方国解。

   命中时给出**整章原句**，好句坏句一眼分明：「如月之恒」出自《天保》，是九如祝颂；
   而同样命中"令仪"的《宾之初筵》，上下文是「醉而不出，是谓伐德」——那是首讽刺饮酒
   失态的诗。
2. **用字档位**——按"见于多少篇"分五档（≥120 极常见 / ≥50 常见 / ≥15 中等 / ≥1 较少
   / 未见），并标出虚词。想要"有典但不烂熟"，落在中等与常见之间最舒服；极常见档基本
   都是 之、不、我、其 这类连接词。档位是**本库内**的相对频率，换了检索范围分母就变，
   `--book 诗经` 与默认 all 之间不要直接对比数字。
3. **读音**——普通话声调、声母、韵母，并列出相邻两字的双声、叠韵、同调关系（这是
   事实描述，不是"拗口"判决）。多音字给出**又读**：`shijing name 单` 会把 shàn 这个
   姓氏读法列出来。
4. **语境**——默认打印命中篇的原文（`--max-context N` 控制篇数，`--no-context` 关闭）。
   这一栏是必需的：语料没有词义字段，"忧""靡""匪"覆盖篇数都很高，但都是需要读完整篇
   才能用的字。诗经一篇最长 613 字（《閟宫》），整篇打得下；四书一篇动辄三千字，所以
   超过约 650 字的篇目只印**命中那几章**，并告诉你怎么读全篇：
   ```console
   $ shijing name 日新
   候选：日新    连用命中 1 处    检索范围：诗经、论语、孟子、大学、中庸（341 篇）
   典籍  分组  篇名  章  原句
   大学  大学  大學  6  湯之盤銘曰：「茍日新，日日新，又日新。」…

   语境（必须自己读，代码不判吉凶，共 1 篇）：
     大学·大學
       第6章：湯之盤銘曰：「茍日新，日日新，又日新。」《康誥》曰：「作新民。」…
       （大学·大學 全篇 16 章 2209 字，此处只印命中章；通读请用 shijing --book 大学 show 大學）
   ```
   「日新」在《诗经》里连用命中 0 处——只看诗经会判它"无典"，其实典在《大学》。

推荐流程：`chars --top 200` 或 `words` 找料 → `name 候选` 验出处 → `show 篇名` 读全篇
→ 自己定夺。项目名同样适用，而且更合适：不涉生辰、不涉重名率，只要"有典、两字真成
词、读起来顺"。

参数口径：`--top` 同时限制"命中句"与"单字出处"各自列出的条数（默认 3）；语境篇数另由
`--max-context` 控制。`--format json` 输出全量——原文不裁窗、语境不裁章、条数不截，
不受这两个参数影响。

## 诚实的边界

写在这里，是为了不让数字看起来比实际更可信：

1. **韵脚已换成上古音口径，但仍不给"韵部定名"。** 逐句是否入韵、韵脚字是哪个、
   同章哪些字互押，全部取自 Baxter《上古音手册》(1992) 押韵字表（CC-BY-4.0，见
   `data/README.md`），不再靠今音猜。可是把互押关系取传递闭包会得到一个 1600+ 字的
   巨簇——少数"合韵"桥字把全库串了起来，这是方法失效的信号而不是分部结果。因此本
   项目只报告逐篇韵式与**可直接核验的互押字对**（如「人/天」互押 23 次）。要给出
   「之部」「幽部」这样的定名，需要一份逐字分部表；维基词典有郑张尚芳体系的数据
   （CC BY-SA-4.0），但 share-alike 会波及本仓库许可，故未并入。
2. **今音口径仍在，但只作对照。** `rhyme --system modern` 保留下来是为了让上面那条
   失真可量化：上古互押的韵类里，只有 **27.4%** 在现代普通话中仍属同一韵母。
3. **章的边界仍沿用原文件的换行。** 原文件有时把两章并成一行，因此 `refrain --what
   parallel` 的"章"粒度在个别篇目上偏细（如《园有桃》把重复的尾句当成独立一章，
   平行度算出 1.0）。篇、句两级是可靠的。
4. **脱字：能确证才补。** 原文件的抓取损伤留下 3 个空洞。两处只带 `?/td>` 残迹
   （《定之方中》「作于?」、《候人》「不?」），缺的是什么字无从确定，**只报告不补**；
   一处是《野有死麕》第2章作「林有朴。，」，Baxter 韵脚表同一句作「林有朴樕」，有据可补，
   于是补，并把理由连同改动一起打进 `build` 的 findings（`corpus.REPAIRS`）。《新台》还有一处：原文件把渲染不出的「泚」拆成部件写成「氵此」，韵脚表同句作「新台有泚」，一并改回——否则字频表里会多出一个不是字的「氵」。
   补得对不对有测试兜着：`test_与韵脚表逐字校验可复现`（该句由长度不等变为逐字一致）与
   `test_脱字只在外部权威给出同一个字时才补`。
5. **分组下界未做权威校验。** 各"之什"的内部归属以文件自身为准，只修正了能靠跨粘贴
   多数表决与覆盖表确定的错位。
6. **串台剔除只保证不误删，不保证不漏删。** 判定要求"尾部整章与本篇其余章不构成
   重章叠句"，因此一条外来整章若**恰好**与本篇平行，就会被留在原地；章数少于 3 的篇
   目也一律不判。当前剔除的是《殷武》尾部 7 章（与《大东》逐字相同）与《蓼莪》尾部
   2 章（与《候人》逐字相同），共 9 章，理由由 `build` 的 findings 逐条打印。另有合成
   用例钉住"平行即保留"（`tests/test_corpus.py::test_尾部套语与本篇平行时不得被误删`）。
   方向是保守的：宁可漏删，不可错删正文。
7. **词频依赖 jieba 通用词典。** 它不认识《诗经》的专名与活用，`心之忧` 这类跨句切片
   会出现。需要更准的词表时，应加一份《诗经》专有词典作为 jieba 用户词典。
8. **`name` 不含任何语义判断。** 它给不出"吉不吉、雅不雅"，因为语料里没有词义与情感
   字段，硬做只会是把使用者的偏好伪装成统计。用字档位的高低只在本库成立，
   与现代汉语的重名率无关；拼音取 pypinyin 的词组默认读法，姓氏与人名用音（单 shàn、
   乐 yuè）只作为"又读"列出，不代替人工审定。
9. **数据文件随仓库分发，不进包。** `data/` 在 src 布局之外，所以只有从仓库根运行
   （或 `pip install -e .`）才找得到语料与韵脚表；`pip install shijing` 那种装法目前
   不给数据。版本只有一个来源 `pyproject.toml`，改版本后需重新 `pip install -e .`，
   否则 `shijing --version` 仍是旧号（这条有测试守着）。

以下四条是并入四书之后新增的边界：

10. **四书的"章"是上游分段，不是传统章句。** 《孟子》上游分 **690 段**，而通行本（赵岐
    章句、朱子《集注》）是 261 章，差了近三倍。所以输出里的「第 N 章」只能定位到"上游
    第 N 段"，**不要拿它去对引文页码或注疏章号**。《大学》16 段、《中庸》39 段取自朱子本
    的分行，且各自只有 1"篇"，`show` 一打就是全篇。
11. **四书经文没有做过逐字对校。** 诗经这一侧有 Baxter 韵脚表可以反证（见下节），四书
    这一侧在本仓库的许可条件下找不到第二份可比对的自由数据（ctext 服务条款禁止抓取，
    维基文库是 CC BY-SA）。因此上游的错字与断句按原样分发。能做到的兜底只有一条：
    `data/books/<slug>/raw.json` 是上游文件的原样存档，出问题时可以直接 diff 回上游。
12. **五部书的字形不统一。** 《论语》是简体（仍残留 2 段作「於」），《孟子》《大学》
    《中庸》是繁体，《诗经》原文以繁为主。统计一律走 `data/t2s.tsv` 归一，所以跨书字频
    可比；但 `show`/`search`/`name` 打印的是原字形——上面那个 `name 徐铎` 就是例子：诗经
    的行是「徐方繹騷」，论语的行是「天将以夫子为木铎」，同一段输出里两种字形并存。
13. **再加典籍要先解决许可与不可逆归一。** 《尚书》《周易》《礼记》《春秋》三传不在仓库
    里，唯一原因是许可：见"再加一部典籍"。另外 `t2s.tsv` 是单向合并表，乾→干、後→后、
    係→系 这几条在诗经里无害（没有对立），但《周易》一旦进来就把「乾卦」和「乾燥」算成
    同一笔账——并入之前得先把这张表拆开。

还有一条**已经修掉的口径缺口**，留在这里是因为它还留着一个尾巴：汉字计数原先只用
基本区字符类 `[一-鿿]`，而归一表里有 **634 条**映射的简体目标落在 CJK 扩展区——于是
「縨→𫄨」「泚→氵此」这类字形在字频里凭空消失，`report` 的「字数」与「字频合计」并排
打印却差 120 处、少 52 个字形。v0.5.1 把字符类扩到基本区 + 扩展 A–G（`corpus.HAN_RANGE`，
叠字与 `name` 的用字提取共用同一张表），现在这两个数完全相等（诗经 29,645 / 全库 86,269），并且有测试钉住（`test_字频合计必须等于字数`）。有趣的是总数恰好还是 29,645——补进一个「樕」、合回一个「泚」；但以前的 29,645 是「字数对、字频少 120」，现在是两边都 29,645。
**尾巴**：仓库里那份韵脚表 CSV 的 `clause` 列是在旧口径下裁剪的，缺这 113 个扩展区字形，
所以逐字校验里有 112 个句对是"长度不等→跳过"而不是"相同"。要彻底对齐，得把裁剪脚本
写进仓库并按新口径重生成 `clause`（`poem`/`idx`/`rhyme_*` 各列不受影响，韵脚统计也不受
影响——它读的是表内自己的文本与位置）。

## 与外部来源的逐字校验

这条以前是空缺的（"没和任何权威本比对过"）。并入 Baxter 韵脚表后可以做了：两边都用
`refrain.sentences` 分句并繁简归一，所以差异只可能来自用字与分句习惯，不会来自标点
或简繁。**只对诗经成立**（四书没有可比对的自由数据，见边界第 11 条）。

这组数字现在由命令产出，不再是一次性脚本的记忆——`shijing rhyme --what verify`：

```json
{ "poems": 305, "aligned_poems": 276, "misaligned_poems": 29,
  "positions": 24828, "identical": 24311, "rate": 0.9792 }
```

`test_与韵脚表逐字校验可复现` 钉住这四个数；改分句口径或改语料都会先撞上它。

- **276/305 篇句数一致**，其中 **97.92%** 的字符位置相同（`24311/24828`）；
- 差异主体是**异体字**：表内「迺」我们「乃」×21、「雝/雍」×14、「昏/婚」×7、
  「殽/肴」×7、「苢/苡」×6、「寘/置」×5——抄本用字习惯不同，不是语料出错；
- 有一族**不是异体字**：表内「公尺」我们「公尸」共 11 处，全集中在《既醉》《鳧鹥》。
  那份表的仓库名里就写着 **ocr**（`baxterocrhymes`），这是它的识别误差——尸/尺形近。
  本项目照原样存档、不改外部数据，只把这条写在这里；受影响的是 `clause` 文本与个别
  韵脚字的字形，韵式与位置统计不受影响；
- 另 29 篇句数不一致，是**分句习惯差异**（如《陟岵》"父曰：嗟/予子行役"与"父曰嗟予子
  /行役夙夜无已"两种读法），字符流本身一致；
- 长度不等的 112 个句对**按跳过处理**（不计为不同），其中一部分是因为表的 `clause` 列
  是在旧的窄字符类下裁出来的（见边界最后一条）。

这次比对还揪出并修好了三处此前漏掉的真缺陷：《殷武》尾部混进《大东》全篇 7 章、
《蓼莪》尾部混进《候人》末 2 章（正文汉字 29,903 → 29,645），以及《野有死麕》《新台》
的脱字与拆字（见边界第 4 条）。串台的判定规则不依赖外部数据，因此 `shijing build`
仍可离线复现，详见 `corpus.drop_stitched_stanzas()`；补字的两条则依赖韵脚表，
所以必须连同理由登记在 `corpus.REPAIRS` 里。

## 再加一部典籍

代码这一侧是三件事，半小时内能做完：

1. `books.BOOKS` 注册一行：`Book('尚书', 'shangshu', PROSE, 'books/shangshu/corpus.json',
   'books/shangshu/raw.json')`；
2. 把上游文件原样放进 `data/books/shangshu/raw.json`，跑 `shijing --book 尚书 build`；
3. 把实测的篇/段/字数填进 `tests/test_books.py::SIZING`，并按上游 blob SHA-1 补一条
   `UPSTREAM` 校验。散文解析器 `parse_prose` 认 `chapter` / `paragraphs` 两种容器（列表
   或单篇对象），空段跳过、整篇无正文直接报错；结构不同就再加一个分支。

卡住的一直不是代码，是**许可**。找过并否掉的来源：

| 来源 | 为什么不能用 |
|---|---|
| ctext.org | 服务条款禁止批量抓取 |
| 维基文库 / Wikisource | CC BY-SA 4.0，share-alike 会传染到本仓库的 MIT |
| daizhigev20/*、chtxt | 仓库根本没有 LICENSE 文件 |
| gujilab/chinese-classical-corpus | 自称 CC0 但 `LICENSE` 是 NOASSERTION，且自述数据抓自 ctext 与维基文库——等于把上面的问题洗一遍再拿来 |
| 中研院漢籍文庫、中國基本古籍庫 | 需注册或付费授权，不允许再分发 |

所以《尚书》《周易》《礼记》《春秋》三传目前不在仓库里。可行的只有两条路：等到一份
**可溯源且真为 MIT/BSD/CC0** 的文本，或者自己做 OCR 与校勘、由本项目产生权利。四书走得通
是因为 chinese-poetry 有真实的 MIT 许可证文件（`Copyright (c) 2016 JackeyGao`），全文随副本
保留在 `data/books/LICENSE.chinese-poetry.txt`。
