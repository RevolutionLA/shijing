# 诗经 · 语料与统计分析

[![CI](https://github.com/RevolutionLA/shijing/actions/workflows/ci.yml/badge.svg)](https://github.com/RevolutionLA/shijing/actions/workflows/ci.yml)

对《诗经》全文做**结构化**与**可复现统计**的 Python 工具包：305 篇 / 30 组 / 约 3 万字，
带命令行、字频词频、复沓（重章叠句）与**上古音口径**的韵脚分析，以及跨平台可出图的字云词云。

```bash
pip install -e ".[dev]"
shijing report              # 一次性输出全部指标
shijing chars --top 10      # 字频
shijing refrain --what shared --top 10   # 跨篇套语
shijing rhyme --poem 关雎               # 逐句韵脚（上古音口径）
shijing name 之恒                        # 候选名的出处、语境、用字档位与读音
```

---

## 这个仓库原来有什么问题

原版是三个各约 20 行的脚本（现留在 [`legacy/`](legacy/)）。重做前先做了数据体检，
结论是：**问题主要不在代码，在数据。**

| 检查项 | 原状态 | 现在 |
|---|---|---|
| 编码 | 三个脚本都写 `encoding='gbk'`，而 `shijing.txt` 实际是 **UTF-8**，直接跑必崩 | 统一 UTF-8，路径可配 |
| 文本路径 | 写死 `C:\xxxxxxxxx\shijing.txt` | `data/raw/` + 自动定位，任意工作目录可跑 |
| 重复粘贴 | 4091 行里 **2514 行（约 61%）是整段重复**；`周頌·清庙之什` 出现 5 次 | 按正文指纹去重，305 篇 |
| 字数 | **84,455** 字，是真实篇幅的 2.8 倍 | **29,645** 字 |
| 繁简混排 | 「周頌」与「周颂」、「撻奮」与简体混在一起，同一个字被拆成两笔账 | 统计走归一字形，存档保留原文 |
| 分组串台 | 粘贴段丢失分组标题，齐风的《南山》等 6 篇被挂在`国风·曹风`下 | 跨粘贴多数表决 + 显式覆盖表 |
| 表格残留 | `维鹈在梁，不?/td>` 这类网页表格残留，且伴随脱字 | 剥离标签，脱字**如实报告**不臆造 |
| 篇名解析 | 五字篇名《昊天有成命》会被漏掉 | 支持 1–6 字篇名 |
| 字云统计口径 | `Counter(text)` 把标点、换行都算成"字" | 只统计汉字 |
| 出图 | 硬编码 `simhei.ttf` + `plt.show()`，无显示环境即崩 | 跨平台字体探测 + 落盘 PNG |

修正后的篇数是**自证式**的：国风 160 / 小雅 74 / 大雅 31 / 周颂 31 / 鲁颂 4 / 商颂 5
= **305 篇**，与《毛诗》篇数完全一致；字数从 8.4 万回落到 2.96 万，也落回《诗经》
应有的量级。这两条都写成了回归测试，防止再退回去。

## 语料结构

`shijing build` 从原始文本重建 `data/corpus.json`：

```jsonc
{ "idx": 1, "group": "国风·周南", "part": "国风", "title": "关雎",
  "stanzas": ["关关雎鸠，在河之洲。窈窕淑女，君子好逑。", ...],
  "versions": 3 }        // 合并了几个重复版本
```

- `data/raw/shijing.txt` — 原始抓取文本，**一字不改地存档**，用于溯源
- `data/t2s.tsv` — 繁→简归一表（4053 条，只登记繁简有别的字），构建期用 zhconv 生成后冻结，**运行时不依赖 opencc/zhconv**
- `data/overrides.json` — 人工裁定表，逐条写明理由，可审计

## 命令

| 命令 | 作用 |
|---|---|
| `build` | 从 `data/raw/` 重建语料；`--regen-t2s` 重建归一表 |
| `chars` / `words` | 字频 / 词频（jieba 分词，可 `--keep-stopwords`） |
| `refrain` | `parallel` 章际平行度、`redup` 叠字、`shared` 跨篇套语 |
| `rhyme` | 韵脚：`--system ancient`（默认，取 Baxter 标注）/`modern`；`--what summary`/`table`/`compare` |
| `cloud` | 字云 / 词云出图，`--font` 可指定字体 |
| `search` / `show` | 全文检索（繁简互通）/ 打印原文 |
| `name` | 候选名核验：连用出处 + 整首语境 + 用字档位 + 普通话读音 |
| `report` | 全部指标一次输出 |

`--format table|json|csv`，`--poem 关雎` 限定单篇。

```console
$ shijing refrain --what shared --top 4
line      poems  where
心之忧矣  11     国风·卫风·有狐、国风·曹风·蜉蝣、国风·邶风·柏舟 …
既见君子  9      国风·周南·汝坟、国风·唐风·扬之水、国风·秦风·车邻 …
万寿无疆  6      国风·豳风·七月、小雅·南有嘉鱼之什·南山有台 …
```

## 拿来给孩子或项目起名

`shijing name 候选名` 不是"取名器"，是**出处核验器**。它只回答能被这 305 篇证实的
四件事，把"这个名字好不好"留给你自己判断。

```console
$ shijing name 之恒 --no-context
候选：之恒    连用命中 1 处
分组       篇名  章  原句
小雅·鹿鸣之什  天保  6  如月之恒，如日之升。如南山之寿，不骞不崩。…

用字：
字  次数    所见篇数  档位   备注
之  1020  230     极常见  虚词
恒  5     3       较少

读音（普通话）：
字  拼音     声调  声母  韵母  又读
之  zhi1   1     zh    i
恒  heng2  2     h     eng
```

四栏各自能防的坑：

1. **连用命中**——两个字都在《诗经》里出现过，不等于它们连用过。`shijing name 德棣`
   命中 0 处：德、棣各自都有，但这个组合是拼的，没这句。此时命令会接着**逐字给出处**，
   让你自己判断这是"有典的拼合"还是"无典的杜撰"：
   ```console
   $ shijing name 徐铎
   候选：徐铎    连用命中 0 处
     《诗经》里没有这两个字连用的句子——单字都有，也可能只是拼凑。

   单字出处：
     徐：（共 6 处，列前 3）
       大雅·荡之什·常武 第4章：率彼淮浦，省此徐土，不留不處，三事就緒。
       大雅·荡之什·常武 第6章：徐方繹騷。震驚徐方，如雷如霆，徐方震驚。
       大雅·荡之什·常武 第10章：如川之流。绵绵翼翼，不測不克，濯征徐国。
     铎：《诗经》全库未见此字。
   ```
   这两条都是有用的信息：《诗经》里的"徐"只出现在征伐徐国的篇章里，全作敌对方国解；
   "铎"字根本不在《诗经》（它出自《周礼》系统的銮铎）。
   
   命中时给出**整章原句**，好句坏句一眼分明：「如月之恒」出自《天保》，是九如祝颂；
   而同样命中"令仪"的《宾之初筵》，上下文是「醉而不出，是谓伐德」——那是首讽刺饮酒
   失态的诗。
2. **用字档位**——按"见于多少篇"分五档（≥120 极常见 / ≥50 常见 / ≥15 中等 / ≥1 较少
   / 未见），并标出虚词。想要"有典但不烂熟"，落在中等与常见之间最舒服；极常见档基本
   都是 之、不、我、其 这类连接词。
3. **读音**——普通话声调、声母、韵母，并列出相邻两字的双声、叠韵、同调关系（这是
   事实描述，不是"拗口"判决）。多音字给出**又读**：`shijing name 单` 会把 shàn 这个
   姓氏读法列出来。
4. **语境**——默认打印命中诗的整首（`--max-context N` 控制数量，`--no-context` 关闭）。
   这一栏是必需的：《诗经》没有词义字段，"忧""靡""匪"覆盖篇数都很高，但都是需要读
   完整首才能用的字。

推荐流程：`chars --top 200` 或 `words` 找料 → `name 候选` 验出处 → `show 篇名` 读全首
→ 自己定夺。项目名同样适用，而且更合适：不涉生辰、不涉重名率，只要"有典、两字真成
词、读起来顺"。

参数口径：`--top` 同时限制"命中句"与"单字出处"各自列出的条数（默认 3）；整首语境
另由 `--max-context` 控制篇数。`--format json` 输出全量，不受这两个参数影响。

## 诚实的边界

写在这里，是为了不让数字看起来比实际更可信：

1. **韵脚已换成上古音口径，但仍不给"韵部定名"。** 逐句是否入韵、韵脚字是哪个、
   同章哪些字互押，全部取自 Baxter《上古音手册》(1992) 押韵字表（CC-BY-4.0，见
   `data/README.md`），不再靠今音猜。可是把互押关系取传递闭包会得到一个 1600+ 字的
   巨簇——少数"合韵"桥字把全库串了起来，这是方法失效的信号而不是分部结果。因此本
   项目只报告逐篇韵式与**可直接核验的互押字对**（如「人/天」互押 23 次）。要给出
   「之部」「幽部」这样的定名，需要一份逐字分部表；维基词典有郑张尚芳体系的数据
   （CC BY-SA-4.0），但 share-alike 会波及本仓库许可，故未并入。
2. **今音口径仍在，但只作对照。** `rhyme --system modern` 保留下来是为了让上面那条
   失真可量化：上古互押的韵类里，只有 **27.4%** 在现代普通话中仍属同一韵母。
3. **章的边界仍沿用原文件的换行。** 原文件有时把两章并成一行，因此 `refrain --what
   parallel` 的"章"粒度在个别篇目上偏细（如《园有桃》把重复的尾句当成独立一章，
   平行度算出 1.0）。篇、句两级是可靠的。
4. **脱字不补。** 原文件有 2 行网页表格残留并伴随丢字（`维鹈在梁，不?/td>`），
   只剥离标签、保留缺口，由 `build` 的 findings 报出来，不做臆测性补全。
5. **分组下界未做权威校验。** 各"之什"的内部归属以文件自身为准，只修正了能靠跨粘贴
   多数表决与覆盖表确定的错位。
6. **串台剔除只保证不误删，不保证不漏删。** 判定要求"尾部整章与本篇其余章不构成
   重章叠句"，因此一条外来整章若**恰好**与本篇平行，就会被留在原地；章数少于 3 的篇
   目也一律不判。当前剔除的是《殷武》尾部 7 章（与《大东》逐字相同）与《蓼莪》尾部
   2 章（与《候人》逐字相同），共 9 章，理由由 `build` 的 findings 逐条打印。另有合成
   用例钉住"平行即保留"（`tests/test_corpus.py::test_尾部套语与本篇平行时不得被误删`）。
   方向是保守的：宁可漏删，不可错删正文。
7. **词频依赖 jieba 通用词典。** 它不认识《诗经》的专名与活用，`心之忧` 这类跨句切片
   会出现。需要更准的词表时，应加一份《诗经》专有词典作为 jieba 用户词典。
8. **`name` 不含任何语义判断。** 它给不出"吉不吉、雅不雅"，因为语料里没有词义与情感
   字段，硬做只会是把使用者的偏好伪装成统计。用字档位的高低只对本库 305 篇成立，
   与现代汉语的重名率无关；拼音取 pypinyin 的词组默认读法，姓氏与人名用音（单 shàn、
   乐 yuè）只作为"又读"列出，不代替人工审定。
9. **数据文件随仓库分发，不进包。** `data/` 在 src 布局之外，所以只有从仓库根运行
   （或 `pip install -e .`）才找得到语料与韵脚表；`pip install shijing` 那种装法目前
   不给数据。版本只有一个来源 `pyproject.toml`，改版本后需重新 `pip install -e .`，
   否则 `shijing --version` 仍是旧号（这条有测试守着）。

## 与外部来源的逐字校验

这条以前是空缺的（"没和任何权威本比对过"）。并入 Baxter 韵脚表后可以做了：把韵脚
标注里的原文去掉标记、繁简归一后与本项目语料逐字对照——

- **267/305 篇句数一致**，其中 **98.09%** 的字符位置完全相同（`24297/24770`）；
- 余下差异几乎全是**异体字**：乃/迺×21、雍/雝×14、婚/昏×7、肴/殽×7、苡/苢×6、
  窕/宨×4、雷/靁×4……是抄本用字习惯不同，不是本项目语料出错；
- 另 38 篇句数不同，抽查确认是**分句习惯差异**（如《陟岵》"父曰：嗟/予子行役"与
  "父曰嗟予子/行役夙夜无已"两种读法），字符流本身一致。

这次比对还揪出并修好了一处此前漏掉的真缺陷：《殷武》尾部混进了《大东》全篇 7 章、
《蓼莪》尾部混进了《候人》末 2 章（正文汉字 29,903 → 29,645）。判定规则不依赖外部
数据，因此 `shijing build` 仍可离线复现，详见 `corpus.drop_stitched_stanzas()`。
